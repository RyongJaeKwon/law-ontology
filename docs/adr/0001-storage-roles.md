# 0001. 저장소 역할 분담: Postgres 원장 · Qdrant 벡터 · Neo4j 그래프

- 상태: 승인
- 날짜: 2026-11-12

## 맥락

이 프로젝트는 세 종류의 검색이 필요하다.

1. **의미 검색**: "신탁재산에 강제집행을 할 수 있나?"처럼 표현이 달라도 뜻이 비슷한 조문 찾기
2. **키워드·식별자 검색**: "신탁법 제22조", "수탁자" 같은 정확한 용어·번호 매칭
3. **관계 탐색**: "이 조문이 위임한 시행령 조문", "이 조문을 준용하는 조문" 찾기

여기에 **원문·출처·수집 이력**을 정확하게 보관할 곳도 필요하다.

검토한 구성은 세 가지다.

| 안 | 구성 | 장점 | 단점 |
|---|---|---|---|
| A | Postgres 하나 (pgvector + Apache AGE) | DB 하나, 트랜잭션·권한 관리 지점 하나 | 하이브리드 검색을 직접 조합해야 함. AGE는 Cypher 지원 범위와 생태계가 Neo4j보다 좁음 |
| B | Postgres + Qdrant + Neo4j (역할 분담) | 각 검색 유형에 맞는 전용 엔진. 하이브리드 검색(dense + sparse) 기본 지원 | 저장소가 셋이라 정합성·동기화 관리 필요 |
| C | 같은 데이터를 pgvector와 Qdrant 양쪽에 운영 | 비교가 쉬움 | 어느 쪽이 정본인지 흐려지고 동기화 부담이 두 배 |

## 결정

**B안을 택한다.** 데이터를 중복 저장하지 않고 **역할로 나눈다.**

| 저장소 | 역할 | 보관하는 것 | 보관하지 않는 것 |
|---|---|---|---|
| **PostgreSQL** | 원장(Source of Record) | 법령·조문 원문 전체, 메타데이터, 출처·수집 이력(source_url, fetched_at, content_hash, 공포번호, 시행일), 청크 원문 | — |
| **Qdrant** | 벡터 검색 | 청크 임베딩(dense + sparse), **필터에 쓰는 최소 payload**(법령 ID, 조번호, 유효기간, 상태, 정의조항 여부 등) | 원문 전체, 인용 목록, 수집 이력 |
| **Neo4j** | 관계 탐색 | **가벼운 노드**(정식 키 + 순회에 필요한 소수 속성)와 관계 | 원문 전체, 수집 이력 |
| **Redis** | 캐시·요청 제한 | 시맨틱 캐시, rate limit 카운터 (3단계에서 도입) | 영속 데이터 |

세 저장소는 **공통 식별자**(조문 정식 키, 청크 ID — ADR 0003)로 조인한다. 공통 식별자가 맞지 않으면 적재 실패로 처리한다.

원칙:
- 원문과 감사 정보는 **Postgres에만** 둔다. Qdrant·Neo4j가 날아가도 Postgres에서 다시 만들 수 있어야 한다.
- Qdrant payload는 **필터에 실제로 쓰는 필드만** 둔다. 늘리고 싶으면 먼저 Postgres 조인으로 해결할 수 있는지 본다.

## 검토한 대안과 기각 이유

- **A안(단일 Postgres)**: 운영은 가장 단순하고 실무에서도 채택되는 구성이다. 다만 이 프로젝트의 학습 목표(전용 벡터 DB의 하이브리드 검색, Cypher 기반 그래프 탐색)를 충족하지 못한다. 대신 **1단계에서 pgvector를 비교 실험 대상으로 측정**해, 같은 평가셋으로 두 구성의 차이를 숫자로 남긴다.
- **C안(이중 운영)**: 비교 목적은 A안 실험으로 대신하고, 운영 경로에는 두지 않는다.

## 결과

- 장점
  - 의미·키워드 하이브리드 검색을 Qdrant 기본 기능으로 쓸 수 있다.
  - 관계 탐색을 Cypher로 표현할 수 있다(예: 위임 2단계 따라가기).
  - 원장이 하나라서 재색인·복구 기준이 명확하다.
- 단점
  - 저장소가 늘어 로컬 메모리 부담이 커진다 → 컨테이너별 메모리 상한 설정(Neo4j 힙 제한 등).
  - 삭제·개정 시 세 저장소에 전파해야 한다 → 삭제 대신 만료(EXPIRE) 처리로 단순화(ADR 0003).
- 후속
  - 1단계: Qdrant vs pgvector 비교 실험 결과를 이 ADR에 링크하거나, 결론이 바뀌면 새 ADR로 대체한다.
  - 키워드 검색을 Qdrant sparse로 할지 Postgres 전문 검색으로 할지는 별도 ADR로 결정한다.
