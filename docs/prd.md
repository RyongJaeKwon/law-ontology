# 법령 지식베이스 RAG 플랫폼 PRD

> 상태: 초안(v0.1) · 작성일: 2026-11-08
> 이 문서는 "무엇을, 누구를 위해, 왜" 만드는지만 다룹니다. "어떻게"는 `docs/design.md`와 `docs/adr/`에서 다룹니다.

## 1. 문제 정의

신탁·자본시장 실무자는 법령 조문이나 유권해석을 찾을 때 법제처 사이트에서 키워드 검색을 반복해야 한다.
"이 상황에 어떤 조문이 적용되나?" 같은 자연어 질문에는 바로 답을 얻기 어렵고, 시행령·해석례까지 함께 찾으려면 시간이 많이 든다.

또한 금융권처럼 **외부 AI API를 쓸 수 없는 폐쇄망 환경**에서는 상용 AI 검색 서비스를 그대로 도입할 수 없다.

## 2. 타깃 사용자

| 사용자 | 주로 하는 일 |
|---|---|
| 신탁·금융 실무자 | 업무 중 관련 조문과 해석례를 빠르게 확인 |
| 법무·컴플라이언스 담당자 | 근거 조문을 정확한 출처와 함께 확인 |
| AI 에이전트(Claude Code 등) | MCP를 통해 법령 검색을 도구로 사용 |

## 3. 목표와 성공 지표

| 목표 | 지표 | 목표치 |
|---|---|---|
| 정확한 근거 검색 | 평가셋 기준 Recall@5 (정답 조문이 상위 5개 안에 포함되는 비율) | 80% 이상 |
| 신뢰할 수 있는 답변 | 출처(조문·해석례 링크)가 포함된 답변 비율 | 100% |
| 근거 없는 답변 방지 | 평가셋 기준 환각(근거와 다른 내용) 비율 | 5% 이하 |
| 응답 속도 | 질문부터 첫 응답 토큰까지의 시간(p95) | 3초 이내 |
| 폐쇄망 대응 | 설정 변경만으로 외부 API ↔ 자체 서빙 모델 전환 | 코드 수정 없이 가능 |

## 4. 유저 스토리

- 실무자로서, 자연어로 질문하면 **관련 조문과 해석례를 근거와 함께** 받고 싶다. 그래야 답변을 믿고 업무에 쓸 수 있다.
- 실무자로서, 답변에 나온 조문을 **클릭해 원문을 바로 확인**하고 싶다.
- 실무자로서, 근거를 찾지 못한 경우에는 지어내지 말고 **"찾지 못했다"고 답해주길** 원한다.
- 개발자로서, Claude Code에서 **MCP로 법령을 검색**하고 싶다.
- 운영자로서, 문서를 수집할 때 **개인정보가 포함된 문서를 자동으로 걸러내고** 싶다.

## 5. MVP 범위

### 포함
- 데이터: 신탁법, 자본시장과 금융투자업에 관한 법률(자본시장법)과 각 시행령, 관련 법령해석례
- 수집 파이프라인: 법제처 Open API 수집 → 개인정보 검사 게이트 → 청킹 → 임베딩(bge-m3)
- 검색: 벡터 검색 + 키워드(BM25) 하이브리드 검색
- 답변 생성: 출처가 포함된 답변, 근거가 없으면 답변 거부
- 웹 채팅 UI
- MCP 서버 (검색 도구 제공)
- 평가셋(질문-정답 50~100쌍)과 자동 평가 스크립트

### 제외 (MVP 이후 검토)
- 판례
- 회원가입·로그인
- GraphRAG, 시맨틱 캐시(Redis)
- 법령 개정 이력 추적, 시점별 법령 조회
- 위 두 법령 외의 다른 법령

## 6. 제약사항

- **장비**: 로컬 MacBook M4 Pro / RAM 16GB → 임베딩만 로컬에서 실행하고, LLM은 OpenAI 호환 API를 사용
- **예산**: AWS 월 2~5만 원 이내, LLM API 비용 별도
- **시간**: 주 11~18시간, 전체 약 4~5개월
- **데이터**: 공개 데이터(법제처 Open API)를 사용한다.
- **법적 고지**: 서비스는 법률 자문이 아니며, 답변 화면에 원문 확인을 권고하는 안내를 표시한다.
